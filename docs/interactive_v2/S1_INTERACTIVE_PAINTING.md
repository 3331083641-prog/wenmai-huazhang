# S1「画中有话」互动油画

> 路由：`/experience/:id`　组件：`frontend/src/features/culture-experience/**`　日期：2026-10-20
> 五件作品、25 处文化线索、15 折故事入口。**全部离线可看，不调用任何模型。**

---

## 1. 这个功能到底解决什么问题

生成图很好看，但用户看不懂：为什么这只猫的眼睛要挑起来？为什么这块是石绿？
现有 `/gallery` 只能给一段 `culture_interpretation` 的自由文本，读完还是不知道「问题出在画上哪个位置」。

S1 把这张图变成一张**可以问的画**：

> 点开画面上的编号 → 先告诉你「这里画的到底是什么」→ 再告诉你「传统为什么这样画」→
> 最后给出来源，你自己去核。

三条不可让步的原则：

1. **画面永不自动移动**。不 autoplay、不自动运镜、不自动滚动，所有缩放/平移/切换都来自用户动作。
2. **位置可以不确定，但不能假装确定**。每处热点带 `locationStatus`，界面显示「已逐点复核 / 约定位」。
3. **先观察，后解读**。`visualObservation` 与 `culturalExplanation` 是两个字段，面板分两段展示，不混着写。

## 2. 交互设计

### 2.1 操作表（全部实测）

| 操作 | 触发 | 结果 |
|---|---|---|
| 选一处线索 | 点击/回车画面上的编号圆点，或点右侧列表 | 面板切换 + 轮廓高亮 + 镜头不动 |
| 下一处 / 上一处 | 面板底部按钮，或 `→` / `←` | 循环切换 |
| 直接跳第 n 处 | `1`–`9` | 跳到对应编号 |
| 放大 / 缩小 | 工具栏 `+` / `−`，或 `+` / `-` 键 | 100% → 150% → 200% → 300% |
| 拖动平移 | 放大后按住拖动 | 视口内平移，边界夹紧 |
| 双击定点 | 双击画面任意位置 | 以该点为中心放大到下一档 |
| 复位 | `0` 键或「复位」 | 回到 100% 且居中 |
| 显示所有位置框 | `H` 键或工具栏开关 | 全部热点轮廓以 34% 透明度显示 |
| 关闭解读 | `Esc` 或面板「收起」 | 回到「从任意一处开始」态 |
| 去故事 | 工具栏 / 面板「在故事里看」 | 跳到 `/story/:id#<chapterId>` |

### 2.2 视觉与状态

- 未选中：圆点半透明金边；hover 时轮廓浮出（不做整块高亮，不糊住画）。
- 选中：轮廓转主题色 + 12% 填充，圆点实心。
- 缩放中：圆点按 `1/max(s,1)` 反向缩放，保持 32px；轮廓线用 `non-scaling-stroke` 保持 1–1.6px。
- 面板：宽屏右栏粘性，窄屏落到画面下方；`aria-live="polite"` 播报「第 n 处线索：标题」。

### 2.3 键盘可达性

6 个圆点都是真实 `<button>`（`tabIndex=0`），`aria-pressed` 反映选中态，
`aria-label="第 n 处：标题"`。`:focus-visible` 有白+朱双环，深色画面上也看得见。

## 3. 实现要点

### 3.1 热点必须挂在「图片真实绘制区」上

见 `ARCHITECTURE.md` §3。核心是 `useContainedImage`：

```ts
const { containerRef, imageBox } = useContainedImage(experience.artworkSize);
// imageBox 是 object-fit: contain 下图片真正占的像素区域
```

容器尺寸一变（窗口 resize、侧栏折叠、手机转屏），`ResizeObserver` 重算 `imageBox`，
热点跟着重排。**实测**：在 1280×800 与 390×844 下，第 1 处圆点都精确落在猫脸中心
（`left = imageBox.x + 0.35 × imageBox.width`，误差 < 1px）。

### 3.2 SVG 叠加层

```html
<svg viewBox="0 0 1 1" preserveAspectRatio="none">
  <ellipse cx="0.35" cy="0.45" rx="0.085" ry="0.085" vector-effect="non-scaling-stroke" />
</svg>
```

用 0–1 坐标系直接画，免去逐点换算；`preserveAspectRatio="none"` 让 1×1 的 viewBox 拉满容器，
配合 `non-scaling-stroke` 让线宽用屏幕像素而非用户单位。

### 3.3 缩放数学

```ts
transform: translate(${(0.5 - fx) * s * 100}%, ${(0.5 - fy) * s * 100}%) scale(${s})
```
`transform-origin: center`。双击定点时把点击处的归一化坐标作为 `(fx, fy)`，
即「让这里到中心来」。位移夹紧到 `±(s-1)*50%`，确保不会拖出画面外露黑边。

### 3.4 错误兜底

`ExperienceErrorBoundary` 是类组件（函数组件无法捕获渲染错误），
出错时显示一句人话 + 「返回文化作品展厅」，而不是白屏。

## 5. 文案纪律

每个热点的 `culturalExplanation` 都必须满足：

- 说「传统工艺/画法通常如何处理」，不说「这幅画一定是某年某人所画」；
- 引用可点开的机构来源（`sourceIds` → `culture_knowledge/sources.json`）；
- 非非遗品类（宋画、青花瓷）**绝不**称为「非遗」；
- 不出现「御窑孤品」「四大年画之首」「XX 博物院珍藏」这类无据表述；
- 生成图里的题字要明确说明「是这张图自带的，不是历史题跋」。

这些不是口头约定，`frontend/tests/data-integrity.test.ts` 里有断言：
出现禁止词直接测试失败。

## 6. 数据生产（坐标怎么来的）

原始 `metadata.json` **没有任何坐标**。流程：

1. 生成 10×10 网格叠加图 `gridf_<style>.png`；
2. 本地 `qwen3-vl:4b-instruct-q4_K_M` 只回答「你指的位置中心落在第几格」（十选一）；
3. 工程把格号换算成归一化坐标并定形状（圆/矩形/多边形）；
4. 按坐标裁小图拼 contact sheet，再让同一个模型复核「这些裁切里是不是真的有那个东西」；
5. IoU 检查是否与其他热点重叠，重叠则删或降级；
6. 结果写入 `frontend/src/data/experiences/<style>.ts`，`provenance.hotspotMethod` 记录方法。

最后一轮复核：`qinghua 4/4 命中，0 重叠`；`jianzhi 5 处中 4 命中，1 重叠`（删重叠项）。

## 8. 局限（照实说）

1. 坐标是工程标注，不是文物测绘；2 处标 `approximate` 并已在界面显示。
2. 面板文字约 120–200 字/处，是「入门级解释」而非学术定论；来源可点开自行判断。
3. 圆点 32px，移动端低于 44px 推荐触摸目标（选择优先不遮挡画面）。
4. 不做热点间连线的「叙事路径」动画（会变成自动播放）。
5. 缩放上限 300%，够看清墨线与针脚，但不做无限放大（原图只有 1024²）。
