# S3「画境漫游」2.5D 分层视差

> 路由：`/wander/:id`　文件：`frontend/src/pages/Wander.tsx`（334 行）、`scripts/interactive/make_layers.py`
> 当前覆盖：**仅《云鹤临水楼》1 件**（其余 4 件显示「暂未开放」）　日期：2026-10-20
>
> **口径先行**：这是「基于图像分层与羽化遮罩的 2.5D 互动视觉体验」，
> **不是**三维重建，**没有**深度模型、**没有**点云、**没有** mesh。
> 界面与文档都按这个说法写，不许出现「真实三维重建」。

---

## 1. 为什么做，又为什么只做一件

**做**：S1/S2 都是「平」的。用户对「画面有纵深」这件事有天然兴趣，
而青绿山水恰好有清晰的远—中—近层次，是最适合验证分层视差的一件。

**只做一件**：每件作品都要逐层做遮罩、调参、目视复核，一件约 40–60 分钟。
本轮预算优先给 S1/S2 的**五件全覆盖**，S3 定位为**技术可行性验证**。
其余 4 件在 `/wander/:id` 会明确显示「这一卷还没有可漫游的分层素材」，
并给出回展厅的出口——不假装能用。

## 2. 分层是怎么来的

`scripts/interactive/make_layers.py`（只读原始成图，不改原图）：

| 层 | 遮罩带（画面纵向 0–1） | 处理 |
|---|---|---|
| `far` 背景 | 全幅不透明 | 模糊 1.4px、饱和 ×0.94（拉开空气感） |
| `mid` 中景 | 0.16–0.30 渐入，0.62 渐出 | 原样 |
| `near` 近景 | 0.52–0.68 渐入 | 反锐化（unsharp），强调松石与水面 |

遮罩是**纵向羽化渐变**（不是硬边裁切），每层输出为带 alpha 的 WebP（q90）：

```
layer-far.webp    91,448 B
layer-mid.webp   181,468 B
layer-near.webp  168,072 B
合计约 430 KB（初版 PNG 为 5.9 MB，改 WebP 后降 93%）
```

**踩坑**：初版 `vertical_ramp()` 返回了宽度为 0 的数组，触发
`IndexError: index 0 is out of bounds for axis 1 with size 0`。
改为返回一维列向量，再由 `alpha_layer()` 用 `np.repeat` 展开成遮罩。

## 3. 渲染：三层 + 透视 + 反向补偿

```html
<div style="perspective: 1400px">                        <!-- 舞台 -->
  <div style="transform-style: preserve-3d;
              transform: rotateX(tx) rotateY(ty) scale(zoom)">   <!-- 画框 -->
    <div style="transform: translateZ(-32.2px) scale(1.023)">far</div>
    <div style="transform: translateZ(  4.6px) scale(0.997)">mid</div>
    <div style="transform: translateZ( 46.0px) scale(0.967)">near</div>
  </div>
</div>
```

### 3.1 为什么要反向补偿

透视会让 `z` 不同的层**自动**放大/缩小（放大率 = `P / (P - z)`）。
如果再额外加一个「近大远小」的 `scale(1 + |depth|×0.035)`，
两层内容尺寸就对不上，羽化带里会出现**双影**。

正确做法是把透视造成的尺寸差**抵消掉**，只保留旋转带来的位移差：

```ts
const z = (depth - 0.5) * 2 * LAYER_GAP;      // LAYER_GAP = 46
const compensate = (PERSPECTIVE - z) / PERSPECTIVE;  // PERSPECTIVE = 1400，与 CSS 一致
transform: `translateZ(${z}px) scale(${compensate})`
```

补偿后：投影尺寸三者一致，**视差只来自 `z·sin(θ)` 的位移**，
在 θ=3.5° 时相邻层相对位移约 3–6px，被 60–80px 的羽化带完全吸收。

### 3.2 对齐实测（关键证据）

把视差关掉（正对画面、无旋转），截图后与原始 `generated.png` 逐像素比对：

```
mean 5.79   p95 25   max 128      （0–255 尺度）
分带均值：
  0.00–0.47   1.3 – 2.6      ← 几乎完全一致
  0.53–0.60   6.1 / 7.8      ← 羽化衔接带，略高但可忽略
  0.67–0.87   2.5 – 4.2      ← 一致
  0.93–1.00  40.8            ← 底部说明条的黑渐变（设计元素，非接缝）
```

结论：**没有重影、没有水平接缝**，差异只来自 WebP 压缩、羽化与底部渐变条。

对比：修正前（含多余 scale）同一测法在 0.61–0.94 带为 **127–145**，
即明显双影——这就是为什么必须做补偿。

## 4. 交互

| 操作 | 行为 |
|---|---|
| 移动指针 | 画面小幅倾斜（`rotateX ±7°`、`rotateY ±9°`），带 120ms 线性过渡与 rAF 节流 |
| 指针离开 | 回到正位（620ms 缓动） |
| 点击某一层 | 该层保持不透明，其余降到 35%，底部提示「正在看：近景 · 松石与水面」 |
| 远眺 / 平视 / 临水 | 三个预设视角，分别 `scale 0.94 / 1 / 1.1` + 固定倾角 |
| 视差开关 | 关闭后锁定正位，保留「分层」但不动（给晕动敏感用户） |
| 方向键 | 键盘也能倾斜（无指针设备可用） |
| 摆正 | 一键回正 |
| 分层说明 | 展开「三层是怎么分的」，写清方法、不是三维重建 |

`prefers-reduced-motion: reduce` 时默认关闭视差。

**晕动控制**：倾角上限很小（≤9°）、过渡很短、无循环动画、无自动运动。
所有动作都是「用户动了才有反应」。

## 5. 文案与免责

界面上常驻一句：`分层视差 · 非三维重建`。
说明面板里写清：

- 分层依据是**画面区域的纵向分带 + 羽化遮罩**，不是深度估计；
- 本轮**没有**加载任何深度模型（Depth Anything V2 权重下载超时，未使用）；
- 因此这不是「从一张图恢复三维」，只是「用分层做出纵深感」。

这三句话同时也是对上一轮调研结论的执行：既然没跑深度模型，就不许借深度模型的词。

## 7. 局限（明确写死）

1. **只有一件**作品有分层素材，其余 4 件暂不支持。
2. 分层是**规则化带状遮罩**，不是语义分割；如果画面主体跨越分带，边缘会有轻微断裂。
3. 没有视差强度滑杆（只有开/关），因为强度过大立刻暴露「分层」而不是「纵深」。
4. 不做指针视差 + 滚动的组合（两者叠加容易晕）。
5. 没有移动端陀螺仪支持（需要权限弹窗，收益不值）。
6. `prefers-reduced-motion` 下默认无动效，这是有意的取舍。
