# S2「一图一境」互动故事页

> 路由：`/story/:id`　文件：`frontend/src/pages/Story.tsx`（397 行）　日期：2026-10-20
> 五件作品各 3 折，共 15 折正文。**滚动驱动镜头，但不劫持滚动。**

---

## 1. 设计意图

S1 是「在画上找东西」，S2 是「顺着这幅画往下读」。

区别在于：S1 把画面当成**地图**，S2 把画面当成**镜头**。同一条文化线索，
在 S1 里是「点开看解释」，在 S2 里是「读到这一段时，画面正好移到它身上」。

三条底线：

1. **不抢滚动**：没有 `preventDefault`、没有 `position: fixed` 的全屏滚动劫持，用户用系统滚动条也能读完。
2. **镜头跟随，不自动播放**：镜头只在「当前章节变化」时移动，速度 700ms，尊重 `prefers-reduced-motion`。
3. **一屏之内看得懂**：每折一个标题、一段正文、若干线索胶囊、若干来源，不堆砌。

## 2. 页面结构（三幕）

```
第一幕 · 卷首
  风格标签 + 标题 + 副标题 + 导语
  右侧：作品小图 + 尺寸说明（1024×1024 · 本地生成图）
  动作：回到互动画境 / 直接跳到第一折

第二幕 · 滚动章节（lg 起双栏）
  左：sticky top-24 的方形画面 + 章节进度条 + 章节点
  右：3 折正文，每折 = eyebrow + 标题 + 正文 + 线索胶囊 + 来源
  窄屏：左栏隐藏，改为正文列顶部的粘性小画面（30vh，最大 280px）

第三幕 · 带走
  复制本页链接 / 导出故事 JSON
  下一件作品推荐
```

## 3. 镜头机制

### 3.1 当前章节的判定

```ts
new IntersectionObserver(cb, {
  rootMargin: '-38% 0px -38% 0px',
  threshold: [0.05, 0.3, 0.6, 0.95],
})
```

取「视口中部 24% 高度带」内可见度最高的那一折作为当前章节。
这个 `rootMargin` 的效果是：**章节标题滚到屏幕中部偏上时切换**，符合阅读预期，
而不是「刚露头就切」。

### 3.2 镜头位移

每折自带一个 `frame: { scale, focusX, focusY }`。渲染时：

```ts
cameraTransform(scale, fx, fy)
  = `translate(${(0.5 - fx) * scale * 100}%, ${(0.5 - fy) * scale * 100}%) scale(${scale})`
```

`transform-origin: center`。这样「焦点 (fx,fy)」被移到容器中心。

以第三折《楼与鹤：画面里最小的人》为例，`frame = { scale: 1.75, focusX: 0.55, focusY: 0.55 }`：

```
translateX = (0.5 - 0.55) * 1.75 * 100 = -8.75%
translateY = (0.5 - 0.55) * 1.75 * 100 = -8.75%
→ translate(-8.75%, -8.75%) scale(1.75)     ← 与实测输出一致
```

负值表示画面整体向左上移，即**楼阁（焦点）向右下让到视野中心**——因为它原本在中心偏右下。

### 3.3 章节内的焦点标记

当前章节 `focusHotspotIds` 命中的热点，在画面上画一个细圈：
半径 `0.014 × 短边 × 2`，最小 10px，颜色用主题金，外圈 `0 0 0 6px` 的同色 13% 光晕。
**只在当前章节显示**，且不是红色实心圆——不糊住画。

### 3.4 章节点与进度

底部一排等宽细条，当前折用主题色填充，点击即 `scrollIntoView({ block: 'center' })`，
`prefers-reduced-motion` 时改 `behavior: 'auto'`。

## 4. 窄屏策略

`lg` 以下，双栏塌成单栏。若照原样把左栏 `hidden`，手机上就只剩文字，故事页会失去「图」。

因此补了一个 `lg:hidden` 的粘性画面块，放在**正文列内部**（这样它能跟着正文一起粘）：

```html
<div class="sticky top-[64px] z-20 lg:hidden">
  <div class="relative mx-auto aspect-square h-[30vh] max-h-[280px]">…</div>
</div>
```

它复用同一个 `cameraTransform()`，因此**手机上也跟着章节走**。
实测（390×844，滚到第三折）：

```
sticky 高度 265px，top 64px，画面框 253×253
camera = translate(-8.75%, -8.75%) scale(1.75)
标签 = 「楼与鹤：画面里最小的人」  3 / 3
```

## 5. 分享与导出（本轮口径）

| 能力 | 实现 | 说明 |
|---|---|---|
| 复制本页链接 | `navigator.clipboard.writeText(location.href)` | **同设备、同浏览器**；失败时退化为 `window.prompt` |
| 导出故事 JSON | 生成 Blob 下载 `wenmai-experience-<id>.json` | 含 id、标题、导语、图片 URL、25 处热点、章节、来源 |
| 跨设备分享 | **未实现** | 没有服务端短链，也不伪造一个「分享链接」 |

导出的 JSON 是**可移植的自描述文件**（`kind: "wenmai-culture-experience"`, `version: "2.0"`），
别人拿到能读懂结构，但目前没有「导入」入口，属于交付物而非产品功能。

## 8. 局限

1. 每件作品固定 3 折，没有做「更多折」的入口（内容成本高于展示收益）。
2. 镜头只有平移 + 缩放，没有旋转/倾斜（倾斜留给 S3，且需要分层素材）。
3. 移动端的粘性画面占 30vh，长文阅读时屏幕可用高度被压缩；已用 `max-h-280px` 封顶。
4. 没有阅读进度持久化（刷新回到第一折）。
5. JSON 导出没有对应导入器，属于「可移植证据」而非完整功能。
