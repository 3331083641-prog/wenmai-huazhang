# 视频参考分析 · 交互式文化体验 v2

> 调研分支：`feat/interactive-v2`　调研时间：2026-10-20　调研员：research-scout
> 本文只做参考分析，不含任何代码改动。

---

## 0. 结论摘要（TL;DR）

**四条抖音短链全部无法获取画面内容。** 服务端一律返回 HTTP 200 + 一段混淆 JS 引导脚本（WAF/风控壳），
没有 `<title>`、没有 `og:title` / `og:description`、没有视频帧、没有评论数。

因此本报告中**关于视频内部的任何描述都是"目标推断"，不是观察事实**。
唯一可用的一手证据是**用户给出的四个标题**（互动油画 / 照片变交互页面 / DeepSeek 小星球 / 低成本交互页面）。

在此前提下，仍可给出可信的工程结论，因为它主要取决于**我们自己仓库的现状**（`App.tsx` 无 `/experience/:id` 路由、
`metadata.json` 无热点坐标、依赖里没有 three.js），而不是视频里到底放了几颗粒子。

| 维度 | 结论 |
|---|---|
| 视频可用画面 | 0 帧 |
| 可用一手信息 | 仅 4 个标题 + 4 个解析后的视频 ID |
| 可信度最高的借鉴点 | 用户主动探索画面 > 自动滚动叙事 |
| 本项目最该先做的事 | 独立故事页 `/experience/:id` + 人工标注热点（P0） |
| 依赖变更 | **无需新增任何依赖**（详见 `OPEN_SOURCE_RESEARCH.md`） |
| S4 小星球的定位 | 概念原型，不阻塞 S1–S3（详见 `S4_TINY_PLANET_RESEARCH.md`） |

## 1. 取证方法与可访问性结论

### 1.1 取证方法

做了两轮探测，都是只读 HTTP 请求，未使用任何第三方解析服务：

1. **`web_fetch` 工具**（走本机配置的 fetch 端点）直接打短链；
2. **PowerShell `Invoke-WebRequest`**，分别用桌面 UA 与 iPhone UA 请求，`-MaximumRedirection 8` 跟随跳转，记录最终 URL、字节数，并用正则提取 `<title>` / `og:*`，再剥掉 `<script>` 统计"可见正文长度"。

### 1.3 四条链接的共同失败特征

- **字节数完全相同（72,914）**，说明四条短链都指向同一个风控中间页模板，内容在客户端 JS 里二次渲染；
- **页面里没有 `<video>`、没有 `playAddr`、没有 `aweme_detail`**，只有 `_$jsvmprt`（字节码解释器）在跑；
- 移动端 UA 拿到的是 2,492 字节的**纯跳转壳**，`from_ssr=1` 也没有吐出 SSR 内容；
- 所有 `title` / `og` / `description` 提取结果为空 —— 连"标题级元数据"都拿不到。

> 换言之：**连视频标题都不是从页面读到的，而是用户自己写给我们四个标签。** 这一点必须在后续任何汇报里保持一致，
> 不能因为"听起来很合理"就把标题当成视频简介。

### 1.4 事实纪律声明

- 本报告**不会**描述视频里的具体特效、镜头参数、配色值、UI 文案、转场时长。
- 凡涉及"视频里大概是这样"的内容，一律标注 **〔推断〕**，其证据等级 = "作品标题 + 交互设计常识"。
- 可信度分级定义：
  - **已观察**：来自实际读到的文本/像素。本报告中视频部分**无任何一条属于此级**。
  - **推断**：由标题语义 + 通用交互模式推出，可能与实际不符。
  - **未核验**：无法访问、无法确认。

## 2. 逐条分析（仅标题级证据）

### 2.1 A · 互动油画

- **可获取信息**：标题「互动油画」四字；视频 ID `7690556199942517937`。
- **可访问性**：HTTP 200，但**无正文、无画面**。
- **能推断的交互模式**〔推断〕：油画类作品的"互动"在 Web 上通常落在这几种之一或组合——
  1. 鼠标/指针移动时画面产生**视差分层**（前景/中景/背景分离，轻微位移）；
  2. **热点（hotspot）**：画面某处可点，弹出该处题材/技法/典故的解释层；
  3. **镜头推进**（Ken Burns / dolly-in）到某局部；
  4. **对比滑杆**（原图 ↔ 风格化/线稿）；
  5. 笔触/颜料类的**粒子或着色器特效**（多为装饰）。
- **为什么倾向 1+2**：标题强调的是"油画"（=静态画作题材）与"互动"。若核心是粒子/着色器，标题一般会写"特效""视觉"；
  而"油画 + 互动"最常见的产品形态就是"可探索的画"，即指针视差 + 点击出解释。这是**推断，不是观察**。
- **可信度**：**低**（仅有标题证据）。

### 2.2 B · 照片变交互页面

- **可获取信息**：标题「照片变交互页面」；视频 ID `7696480662933411490`。
- **可访问性**：同 A，无正文、无画面。
- **能推断的交互模式**〔推断〕：这类内容通常是"把一张平面照片做成能响应指针的页面"，
  技术路径大概率是 **2.5D 视差**（把照片按深度切成若干层，指针移动时各层以不同速度位移），
  进阶版用单目深度估计生成深度图后做**位移贴图（displacement）**或点云。
- **对本项目的价值**：**这是四条里和我们最贴近的一条**。我们的输入就是 5 张"平图"（生成的 1024×1024 作品），
  它证明"平图 → 可交互页面"是可行且被当作作品展示的路线。
- **可信度**：**低–中**（标题语义明确指向"平图→交互"，但实现细节全为推断）。

### 2.3 C · DeepSeek 小星球

- **可获取信息**：标题「DeepSeek 小星球」；视频 ID `7698384083505111545`。
- **可访问性**：同 A，无正文、无画面。
- **能推断的交互模式**〔推断〕：标题里的"小星球"几乎必然指向**球体视觉**（sphere / 星球式入口），
  常见形态是：一个可拖拽旋转的球，球面贴作品图或缩略图，点击某点进入对应内容。
  "DeepSeek"出现在标题里，说明该视频的**制作手段**可能包含用大模型生成代码或文案（即"低成本做一个星球页"）。
- **重要澄清**：即使视频里真是一个漂亮球体，**它大概率也不是真全景**。用少量方图贴球面得到的是"概念化星球"，
  不是全景重建。详见 [`S4_TINY_PLANET_RESEARCH.md`](./S4_TINY_PLANET_RESEARCH.md)。
- **可信度**：**中**（"星球=球体"这一层推断相当可靠；其余全不可知）。

### 2.4 D · 低成本交互页面

- **可获取信息**：标题「低成本交互页面」；视频 ID `7698429311326510201`。
- **可访问性**：同 A，无正文、无画面。
- **能推断的交互模式**〔推断〕：标题的落点是**"低成本"**，不是"炫技"。这类内容通常主张：
  用 CSS/DOM 动画 + 少量 JS 做出"看起来很贵"的页面，**不引入 3D 引擎**。
- **对本项目的价值**：**最高**。它的主张与我们的约束完全一致（React 19 + motion + 无 three.js），
  也与我们"本轮不堆特效"的判断互相印证。
- **可信度**：**低**（"低成本"是价值主张，不是可观察事实）。

## 3. 分类表

### 3.1 值得借鉴的交互（按对我们的价值排序）

| 交互模式 | 来自 | 为什么值得借鉴 | 证据等级 |
|---|---|---|---|
| **用户主动探索画面**（指针/触摸驱动，画面响应） | A、B | 把"看画"变成"逛画"，是文化解释的天然载体；无需模型与素材 | 推断 |
| **点击热点 → 出信息层** | A | 直接对应我们的目标"点击热点看文化解释"；实现成本最低，收益最直接 | 推断 |
| **滚动叙事**（分章节推进故事） | A、D | 适合"独立互动故事页"；但要防止劫持滚动 | 推断 |
| **鼠标视差**（分层位移） | B | 用 1 张平图 + 2–3 层遮罩即可，性价比高 | 推断 |
| **镜头推进**（局部放大 + 运镜） | A、C | 引导注意力到纹样细节，是"文化解释"的好前置动作 | 推断 |

### 3.2 大概率只是视觉装饰（不要抄）

| 装饰项 | 说明 | 判断 |
|---|---|---|
| 粒子 / 星空 / 尘埃 | 与"纹样文化解释"无信息关联，纯氛围 | 不做（移动端掉帧、喧宾夺主） |
| 泛光 / Bloom / 色差 / 噪点 | 后期特效，成本高、易显廉价 | 不做 |
| 品牌动效（Logo 演绎、开场大动画） | 一次性消费，第二次访问即成负担 | 不做（最多 1 次轻量淡入） |
| 假 3D（CSS 倾斜卡片伪装立体） | 转动时有明显"纸片"感，反而降低质感 | 不做 |
| 自动播放的运镜 | 用户失去控制权，且与"主动探索"相悖 | 不做 |

> 注意：以上"不做"的理由是**与本项目的目标不匹配**，不是断言视频里没有这些。视频我们没看到。

### 3.3 实现归属：纯前端可直接做 vs 需要额外素材/模型

| 需求 | 纯前端可行 | 需要额外素材 | 需要模型/服务 |
|---|---|---|---|
| 热点标注 + 点击弹层 | ✅ DOM + 绝对定位百分比 | 需要**人工标注坐标**（见 §4.1） | — |
| 指针视差（分层） | ✅ CSS `transform: translate3d` | 需要**分层图**（人工切 2–3 层或渐变遮罩） | — |
| 滚动叙事章节 | ✅ `motion` 的 `useScroll` / `scroll` API | — | — |
| 镜头推进（局部放大） | ✅ `transform: scale()` + `transform-origin` | 高分辨率局部图更佳 | — |
| 图片对比滑杆 | ✅ `clip-path` + pointer events | — | — |
| 真 2.5D 深度视差（像素级位移） | ⚠️ 需要深度图 | — | 需要单目深度模型（**建议不做**，见 OPEN_SOURCE_RESEARCH） |
| 球面贴图星球 | ❌ 需 WebGL | 方形图会被拉伸 | — |
| 载入即"AI 讲解"文案 | ✅ 读现有 `metadata.json` | — | — |

## 5. 本轮「不做什么」

写清楚"不做"，比写"要做"更能保护交付。

| 不做 | 理由 |
|---|---|
| **不堆特效** | 粒子/泛光/噪点与"纹样文化解释"零信息关联；移动端掉帧；评审记不住特效，只记得"看不懂"。 |
| **不做假 3D** | CSS 倾斜卡片、伪透视在转动瞬间会暴露"纸片感"，比不做更差。要真 3D 就上 WebGL，要不起就不做。 |
| **不做自动滚动 / scroll-jacking** | 劫持滚轮、强制推进、不可跳过——这是展演现场最容易被观众判死刑的交互。滚动只能"驱动动画"，不能"夺走控制"。 |
| **不做自动播放的运镜** | 与"用户主动探索"直接冲突；也剥夺了用户"停下来看细节"的权利。 |
| **不做需要下载权重的功能** | 单目深度模型需 PyTorch/GPU + 权重，与"低成本、可离线展演"冲突（详见 OPEN_SOURCE_RESEARCH）。 |
| **不新增第三方 UI/动画依赖** | 现有 React 19 + motion 12 已覆盖全部 P0/P1 需求。 |
| **不基于本次视频做任何"还原"承诺** | 四条视频均未取到画面，任何"照视频做"的说法都是编造。 |
| **不把球体说成"全景重建"** | 用 1024×1024 方图贴球面 ≠ 全景，术语必须准确，见 S4。 |
