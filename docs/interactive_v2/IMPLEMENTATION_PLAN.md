## 0. 总目标与边界

把「上传参考图 → AI 创作 → 生成文化作品」这条**已经跑通**的链路，
延长成「…→ 理解文化元素 → 互动探索 → 文化故事 → 文创转化」，且：

1. 不破坏 `/creator`、`/gallery`、`/products`、`/generate`、`/analyze-image`；
2. 不新增前端依赖（已调研，见 `OPEN_SOURCE_RESEARCH.md`）；
3. 互动内容必须**离线可看**，不能依赖模型在线；
4. 每一处文化解读都要能点开来源，不虚构馆藏、排名、非遗身份；
5. 全部坐标、文案、来源可审查、可单测。

## 2. 里程碑与关键决策

### M0　先把「能不能做」查清楚（17:35 前）

| 决策 | 结论 | 依据 |
|---|---|---|
| 是否参考四条抖音视频实现 | **不能**，四链全部返回风控壳，0 帧可用画面 | `VIDEO_REFERENCE_ANALYSIS.md` |
| 是否引入 GSAP | 不引入 | 许可为 Webflow 非 OSI，`license: null` |
| 是否引入 react-compare-slider | 不引入，原生实现 | 与热点层 pointer 事件耦合，自己写更可控 |
| 是否用 Depth Anything V2 | 不用 | 仅 Small 为 Apache-2.0，权重两次下载超时（`huggingface.co`） |
| 是否重建三维 | 不重建 | 无多视角素材，强行重建必然「假 3D」 |
| 热点从哪来 | 本地 Qwen3-VL 给 10×10 候选格 → 工程定坐标 → 裁切复核 | 自由框不可用（见下） |

### M1　数据层先行（17:44–17:50）

先写 `types.ts` → `schema.ts` → `geometry.ts`，再写任何 UI。
理由：坐标错了 UI 再漂亮也是错的；先让数据能被机器检查。

**踩坑**：Zod 4 的 `z.tuple` 推断成 `[number?, number?, ...unknown[]]`，
导致 `geometry` 在 union 里被推断为可选，`tsc` 报 TS2344。
解决：`z.custom<[number, number]>` 自写 point 校验 + `geometryField` 断言，
把 union 的 optionality 打掉。

### M2　坐标生产（17:50–18:00）

流程：`gridf_*.png`（10×10 网格叠加）→ 本地 VLM 只回答「中心点落在第几格」→
工程换算成归一化坐标 → 裁切拼成 contact sheet → 同一个 VLM 复核「这批裁切对不对」→
IoU 与重叠检查。

**为什么不让 VLM 直接给框**：实测自由框误差常达 0.1–0.2 归一化（约 100–200px），
基本不可用；而「中心落在第几格」是十选一，准确率高得多。

**复核结果**（最后一轮）：
`qinghua: 4/4 命中、0 重叠`；`jianzhi: 5 处中 4 命中、1 重叠 → 删掉重叠项`；
最终 25 处定稿，其中 `zhuxianzhen` 顶部题名横带标 `approximate`（文字带边界本身模糊）。

### M3　S1 交互油画（18:00–18:12）

三件事按顺序做：
1. **contain 数学**：先让热点在任意容器都贴住画面（`useContainedImage`）；
2. **操作模型**：缩放/拖拽/双击定点/键盘，任何一个都不许「自动动」；
3. **解读面板**：先「画面里有什么」再「它为什么这样」，来源可点。

**布局踩坑**：初版画面在 1280×800 首屏被切掉 37px（y=312 + 720）。改成
`width: min(100%, calc(100vh - 330px), 720px)` + 把工具栏并入左列，
使画面底边 790 < 800，整幅画在首屏完整可见。右侧面板高度
`calc(100vh - 16.5rem)` 同理收敛。

### M4　S2 故事页（18:12–18:23）

`IntersectionObserver`（`rootMargin: -38% 0 -38%`）驱动「当前章节」，
章节切换时画面上做 `translate + scale` 的镜头运动；**不劫持滚动**，
不 autoplay、不自动播视频。

窄屏补强：`lg` 以下左侧画面原本整块 `hidden`，等于手机上只剩文字。
补了一个 `lg:hidden` 的粘性小画面（30vh，最大 280px），复用同一 `cameraTransform()`，
滚动时仍跟着章节走。

### M5　S3 分层视差（18:23–18:31）

`scripts/interactive/make_layers.py`：读 1024×1024 成图 → 按纵向带生成羽化遮罩 →
far 全幅 + 轻微模糊/降饱和，mid 中段，near 下段 + 反锐化 → 输出 WebP q90。

**踩坑 1**：初版输出 PNG，三层共 5.9MB（1442/2140/2305 KB）→ 改 WebP q90，
降到 89/177/164 KB（合计 430KB）。

**踩坑 2**：初版每层加 `scale(1 + |depth|*0.035)` 制造「近大远小」，但透视本身已在放大，
两者叠加会让相邻两层内容大小不一致，羽化带里出现双影。
改成**反向补偿** `scale((P - z) / P)`（P=1400 与 CSS `perspective` 一致），
只保留旋转带来的位移差（视差），尺寸完全对齐。

**对齐实测**：把视差关掉后，页面渲染结果与原始 `generated.png` 逐像素比对：
`mean 5.79`、`p95 25`；分带看，衔接带（0.53–0.60）为 6–8，其它带 2–4，
说明**没有重影、没有接缝**，差异只来自 WebP 压缩与边缘羽化。
