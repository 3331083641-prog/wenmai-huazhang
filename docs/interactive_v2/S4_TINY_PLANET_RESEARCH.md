## 1. 球体视觉的原理拆解

### 1.1 球面 UV 贴图

`SphereGeometry(radius, widthSegments, heightSegments)` 生成的 UV 是**等距柱状（equirectangular）**布局：

| 轴 | 映射 | 含义 |
|---|---|---|
| `u`（0→1） | 方位角 φ 从 −π 到 +π | 绕赤道一圈 = 360° |
| `v`（0→1） | 极角 θ 从 0（北极）到 π（南极） | 从北极到南极 = 180° |

关键推论：**一个球面天然"期望" 2:1 的图**（360° : 180°）。
把非 2:1 的图贴上去，要么横向拉伸，要么纵向拉伸，没有第三条路。

### 1.2 两极必然畸变

`v → 0` 或 `v → 1` 时，整行像素被压缩到一个点。任何图贴满全球面，**南北极都会出现"捏饺子"式的放射状挤皱**。
业界标准做法（Google Earth、全景播放器）都靠 2:1 全景图 + 极点区域本来就是天空/地面来掩盖这一点。
**我们的作品图没有"天空/地面"，所以极点畸变会直接落在画面主体上。**

### 1.3 相机：正交 vs 透视

| | 透视相机 `PerspectiveCamera` | 正交相机 `OrthographicCamera` |
|---|---|---|
| 观感 | 有近大远小，像"看一个球" | 无透视，像"一张会转的圆形图" |
| 适合 | **小星球 / 星球入口**（推荐） | 仪表盘、地图、需要尺寸恒定的 UI |
| 参数建议 | `fov ≈ 40–45`，相机 `z ≈ 2.6–3.0`（半径 1 时） | `frustum` 半高 ≈ 1.2 |

> 想要"小星球"的味道，**必须用透视**。正交会让球看起来像贴纸。

### 1.4 拖拽旋转（四元数，不要用欧拉角）

```
// 原理：把"屏幕上的水平/垂直拖动"变成"绕世界 Y 轴 / 绕相机 X 轴"的旋转，左乘到当前朝向
yawQ.setFromAxisAngle(worldUp,   -dx * ROT_SPEED)
pitchQ.setFromAxisAngle(cameraRight, -dy * ROT_SPEED)
sphere.quaternion.premultiply(pitchQ).premultiply(yawQ)
```

要点：
- **用 `premultiply`（左乘）**，因为旋转轴是**世界/相机空间**，不是物体局部空间；用右乘会导致"越转越歪"；
- **不要** `rotation.y += dx; rotation.x += dy`：欧拉角会万向节死锁，且在极点附近手感崩坏；
- **加阻尼**：保存 `targetQuaternion`，每帧 `slerp` 到目标（`1 - Math.pow(0.001, dt)` 之类），松手后惯性衰减；
- **限制俯仰**：pitch 累积到 ±85° 就该收住，否则球会"翻过来"，用户失去方向感；
- **`pointerdown` 时 `setPointerCapture`**，避免鼠标移出元素后丢事件。

### 1.5 缩放

- 不要用 `camera.position.z` 直接改（会破坏阻尼）。
- 维护 `targetDistance`，滚轮/双指 `wheel`/`touchmove` 改目标值，每帧 `camera.position.z += (target - current) * k`。
- 夹紧范围，例如 `[2.0, 4.5]`，防止穿进球里或缩成一个点。
- **移动端不要监听 `wheel`**，用双指 `pinch` 或干脆不缩放（热点点击已够用）。

### 1.6 进入场景转场

三条常见路径，成本递增：

| 方案 | 做法 | 成本 | 风险 |
|---|---|---|---|
| **A. 淡入 + 缩放** | 球从 `scale 0.85 → 1` + 透明度 0→1 | 极低（纯 CSS/`motion`） | 无 |
| **B. 相机推进** | 相机 `z` 从 4.5 → 2.8，同时轻微 `fov` 收窄 | 中 | 与滚轮缩放逻辑冲突 |
| **C. 飞向热点** | 相机位置 `lerp` 到该热点表面点法线方向 + 四元数 `slerp` 使热点正对相机，然后淡出到故事页 | 高 | 需要"球面点 → 世界坐标"的反算，且要处理"绕远路还是走近路" |

> **建议只用 A**。C 看起来最炫，但它是"自动运镜"，与 [`VIDEO_REFERENCE_ANALYSIS.md`](./VIDEO_REFERENCE_ANALYSIS.md) §5
> 「不做自动运镜」的原则冲突，且实现风险最高。

## 2. 用现有素材做球体的"真实效果边界"

### 2.1 素材实测

| 素材 | 实测尺寸 | 比例 | 贴球面的后果 |
|---|---|---|---|
| `generated.png`（5 张作品图） | **1024 × 1024** | **1:1** | 横向拉伸 **≈2.0×**（因为球面期望 2:1） |
| `reference.png`（5 张参考图） | 1254 × 1254 | 1:1 | 同上 |
| `culture_card.png`（文化卡） | **1080 × 1440** | **3:4（竖）** | 纵向拉伸 **≈2.67×**，变形更严重 |

> 数据来源：对 `docs/examples/*/` 下 PNG 逐个读 `System.Drawing.Image.Width/Height`，15 个文件全部核对。

### 2.2 三条硬边界

1. **不能叫"全景重建"。**
   全景（panorama / 360° photo）的前提是**拍摄或渲染出 360°×180° 的环境图**（通常 2:1）。
   我们只有一张**平面作品图**，贴到球上得到的是"把画印在球上"，不是"进入画的空间"。
   **正确术语：球面贴图概念原型（sphere-mapped concept prototype）。**
   在任何文档、答辩、README 里都不得写成"全景重建""3D 还原""沉浸式漫游"。
2. **横向拉伸不可避免，除非裁切。**
   1:1 图 → 2:1 球面，要么接受 2 倍横向拉伸（画面主体变胖），要么**裁掉上下**（损失构图），要么**只贴赤道带**（见 2.3）。
3. **极点畸变必然发生，除非不贴两极。**
   这是 `SphereGeometry` 的几何属性，不是参数调优能解决的。

### 2.3 让"1:1 图贴球"不那么难看的三个技巧

| 技巧 | 做法 | 效果 | 代价 |
|---|---|---|---|
| **只贴赤道带**（推荐） | 把球面 `v ∈ [0.25, 0.75]` 之外改为纯色/渐变；图只占中间 90° 纬度带 | 极点畸变消失；拉伸局限在可接受范围 | 需要自定义 UV 或第二个球壳 |
| **重复平铺（repeat）** | `texture.wrapS = RepeatWrapping; texture.repeat.x = 2` | 图横向重复两次，视觉上像"纹样绕球一周" | 会出现接缝；对构图不友好的图（如居中主体）会变成"两个主体" |
| **贴图 + 描边框** | 球体本身用低饱和底色，图作为"贴片"（`decal` 或小平面）贴在球面若干位置 | 最接近"星球上挂着五件作品"的真实需求 | 需要 5 个 `PlaneGeometry` + 法线朝向计算（即热点方案） |

> **推荐路径：不做"球面贴满图"，改做"素球 + 五个作品贴片/热点"。**
> 这样：图不会被拉伸（贴片是平面，1:1 比例保持）、极点畸变无所谓（素色球）、
> 而且**正好就是产品需求**——五个入口，点进五个故事页。

### 2.4 结论

| 说法 | 是否成立 |
|---|---|
| "用 5 张作品图做一个可旋转的小星球" | ✅ 成立（素球 + 贴片/热点） |
| "用 5 张作品图做全景重建" | ❌ **不成立**（素材不是全景图） |
| "球面贴满作品图，效果会很好" | ❌ 不成立（拉伸 2× + 极点畸变） |
| "这是 3D 还原了展厅" | ❌ 不成立（无空间信息、无模型） |

## 3. 技术选型对比

### 3.1 三条路线

| 维度 | **A. 原生 three.js** | **B. @react-three/fiber** | **C. 纯 CSS 3D** |
|---|---|---|---|
| 真球面 UV | ✅ | ✅ | ❌ **做不到**（见 3.3） |
| 代码量（一个球 + 5 热点） | 中（约 200–260 行） | 中（约 160–200 行，但要学 r3f 心智） | 低（约 80–120 行） |
| 与 React 19 集成 | 需 `useEffect` + `ref` 手动挂载/销毁 | ✅ 原生 JSX | ✅ 纯 DOM |
| 包体积（npm unpacked，实测） | `three@0.186.1` **19,964 KB** | three + `@react-three/fiber@9.8.2` **2,343 KB** | **0 KB**（无依赖） |
| 传递依赖 | 0 | **13 个**（zustand / scheduler / its-fine / …） | 0 |
| React 版本约束 | 无 | `react >=19 <19.4` ← **本项目 19.2.5 可用但会被将来版本卡住** | 无 |
| 射线拾取热点 | 手写 `Raycaster`（约 15 行） | 直接 `onClick` 到 mesh | 手动算角度 |
| WebGL 降级 | 需自己判断 + 降级 | 需自己判断 + 降级 | 天然无 WebGL 需求 |
| 学习/维护成本 | 低（API 稳定 10 年+） | 中（抽象层，需理解 `useFrame`/`Canvas` 生命周期） | 极低 |
| 适合本项目？ | ✅ **若 S4 立项，首选** | ⚠️ 若团队已熟 r3f 可选 | ✅ **若只求"能转的球"** |

> 体积说明：`unpackedSize` 是 npm 包解压体积，**不等于 bundle 体积**。
> 打进 bundle 的是 tree-shake 后的子集，**本报告未实测 gzip 后字节数**。
> 但可以确定的是：**three 是本轮所有候选里体积代价最高的一个**，比 `motion`（857 KB unpacked）高一个数量级。

### 3.2 推荐

> **若 S4 立项：选 A（原生 three.js）。**
> 理由：只做一个球 + 5 个热点，r3f 的抽象层省不了多少代码，却多带来 13 个传递依赖和一个 `react <19.4` 的上限。
> **若只想验证"球能不能转起来"：选 C（纯 CSS）**，零依赖，一周内能出可点原型，但接受"它不是真球"。

### 3.3 为什么纯 CSS 3D 做不出真球（技术边界，必须写清）

CSS 3D `transform` 的本质是**对平面做仿射变换**（旋转/缩放/倾斜/平移）。
它**没有曲面**，因此**无法把一张图 UV 映射到球面**。常见的三种"假装"：

| 假装法 | 实际效果 | 问题 |
|---|---|---|
| 一圈平面围成圆柱（carousel ring） | 像"旋转的环/灯笼" | 有棱、顶部是空的，**不是球** |
| N 个小平面拼多面体（disco ball） | 远看像球 | DOM 数量爆炸（60+ 元素）、接缝明显、性能差 |
| 圆形 `div` + `background-position` 动画 | 像"贴在圆盘上转的画" | **没有立体感**，本质是 2D 动画 |

> 结论：**纯 CSS 只能做"圆形入口 + 伪旋转"，不能做"球面贴图"。**
> 如果产品要的是"氛围"而不是"球"，纯 CSS 足够；如果要"球"，必须 WebGL。

## 4. 与 S1–S3 的关系

### 4.1 依赖关系（谁挡谁）

| 阶段 | 内容 | 是否被 S4 依赖 |
|---|---|---|
| **S1** | `/experience/:id` 故事页 + 人工热点 + 信息层 | ✅ S4 的点击目标**就是** S1 的路由 |
| **S2** | 指针视差 / 镜头推进 / 滚动章节 | ❌ 不依赖 |
| **S3** | 五个作品的热点内容、文案、降级路径 | ✅ S4 的五个热点需要 S3 的 `label`/`body` |
| **S4** | 球体入口（本文） | 依赖 S1 + S3 已完成 |

> 也就是说：**S4 是 S1+S3 的下游**。S1/S3 没验收，S4 的热点点了没地方去。

### 4.2 硬约束

> ## ⚠️ S4 不得影响 S1–S3 交付
>
> 具体化为四条可检查的规则：
>
> 1. **顺序门禁**：S1、S2、S3 全部通过验收（含降级路径与无障碍）之前，**不新建 S4 分支、不装 `three`**。
> 2. **依赖隔离**：S4 若引入 `three`，必须**只在该路由的 chunk 内**（`React.lazy` + 动态 `import()`），
>    不得进入主 bundle。主 bundle 的 gzip 体积**不得因 S4 增长**。
> 3. **功能可关**：S4 必须有独立开关（环境变量或路由开关），关闭后 `/experience/:id` 与 `/gallery` **完全不受影响**。
> 4. **失败可退**：WebGL 不可用 / 低端设备 / `prefers-reduced-motion` 时，**自动退化为静态图入口**，
>    不允许白屏、不允许"请升级浏览器"。
>
> 一句话：**S4 是锦上添花，S1–S3 是交付物。冲突时永远牺牲 S4。**

## 5. 最小可验证原型规格（若未来立项）

### 5.1 目标（只有这些，不多做）

一个页面、一个球、五个热点、点击进故事页、无 WebGL 时退化为静态图。

### 5.2 功能规格

| # | 项 | 规格 | 验收 |
|---|---|---|---|
| 1 | 路由 | `/sphere`（**不要**占用 `/experience`，避免与 S1 冲突） | 直达 URL 可打开；刷新不 404（注意 `HashRouter` 分支） |
| 2 | 球体 | `SphereGeometry(1, 48, 32)`，素色材质（不用贴满作品图） | 无极点畸变、无接缝 |
| 3 | 灯光 | 1 个环境光 + 1 个方向光，够看出体积即可 | 不出现"死黑"或"过曝" |
| 4 | 旋转 | 拖拽旋转（四元数 + 阻尼），俯仰限制 ±85° | 手感连续；不万向节死锁 |
| 5 | 缩放 | 滚轮/双指，`distance ∈ [2.0, 4.5]` | 不穿模、不缩成点；移动端可不支持 |
| 6 | 五个热点 | 5 件作品各 1 个点，均匀分布（经纬度预设即可，不做自动布局） | 五个点都可点中；不重叠 |
| 7 | 热点样式 | 小圆点 + `hover/focus` 放大 + 作品名标签 | 键盘 Tab 可依次聚焦 |
| 8 | 点击行为 | 跳 `/experience/:id`（`styleId` ∈ 五个已知值） | 五个点分别到五个正确页面 |
| 9 | 降级 | 无 WebGL / `prefers-reduced-motion` → 显示 5 张静态卡片 | 强制关闭 WebGL 后仍可用 |
| 10 | 卸载 | 路由离开时 `dispose()` 几何体/材质/纹理，`cancelAnimationFrame` | 反复进出 20 次不涨内存 |

### 5.3 性能预算

| 指标 | 预算 | 说明 |
|---|---|---|
| 该路由 chunk（gzip） | **≤ 180 KB** | 含 three 子集；**实测为准，本文不给承诺值** |
| 首帧可交互 | ≤ 1.5 s（中端笔记本） | 球体无纹理，应远快于此 |
| 稳态帧率 | ≥ 50 fps | 一个球 + 5 个 sprite，压力极小 |
| 纹理 | **0 张**（素球） | 若必须贴图，单张 ≤ 1024²，`generateMipmaps: true` |
| 像素比 | `Math.min(devicePixelRatio, 2)` | 防止 4K 屏烧 GPU |
| 上下文 | 1 个 WebGL context，离开路由必须释放 | 浏览器上限约 8–16 个 |

### 5.4 明确不做（原型阶段）

- ❌ 不做星空背景、粒子、光晕、Bloom
- ❌ 不做"飞入球体"的自动运镜（见 §1.6）
- ❌ 不做球面贴满作品图（见 §2.3）
- ❌ 不做自动旋转（会与用户拖拽争夺控制权；若要，仅在用户 5 s 无操作后低速转，且拖拽即停）
- ❌ 不做物理、碰撞、惯性抛出
- ❌ 不做深度图、不做 3D 模型、不下载任何权重

### 5.5 验收清单（复制即用）

```
[ ] /sphere 直达可打开，刷新不 404
[ ] 球体无极点畸变、无接缝
[ ] 拖拽旋转连续、有阻尼、不万向节死锁
[ ] 俯仰被限制在 ±85°
[ ] 五个热点均可点中，分别跳转正确 /experience/:id
[ ] Tab 可依次聚焦五个热点，Enter 可触发
[ ] 强制禁用 WebGL 后自动降级为 5 张静态卡片
[ ] prefers-reduced-motion 下无自动动画
[ ] 路由离开后 WebGL context 被释放，反复进出 20 次内存不增长
[ ] 主 bundle gzip 体积与 S4 前一致（S4 只在自己的 chunk 里）
```

## 6. 最终判断

| 问题 | 回答 |
|---|---|
| 本轮做不做 | **不做。** `docs/interactive_v2` 本轮目标是"五张作品 → 点击热点 → 独立故事页"，球体不在其中 |
| 未来做的前提 | S1–S3 全部验收 + 有独立人天 + 接受"概念原型"而非"全景"的定位 |
| 如果非要做，先做什么 | §5 的最小原型（素球 + 5 热点 + 降级），**先跑通再谈视觉** |
| 最容易被误解的说法 | "全景重建""3D 还原展厅""沉浸式漫游" —— **三个都不许用**，正确说法是"球面贴图概念原型 / 圆形入口" |
| 最大的隐性成本 | 不是写代码，是**后续每次改作品都要同步五份热点坐标与球面位置** |

> 一句话给主工程师：**先把 `/experience/:id` 做扎实。球体是一个漂亮的入口，但它不是体验本身；
> 而一个点进去只有"敬请期待"的球，比不做更伤。**
