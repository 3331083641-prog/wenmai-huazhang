# 二层楼梯井「看得见」的修复记录（2026-10-23）

问题：灵宠已经能上下楼（走位数据见 README），但从二层看过去，楼梯口只是一圈栏杆，
里面像是一整片地面，视觉上楼梯根本没有通上来。

## 根因：三层板叠在一起

| 层 | 节点 | 情况 |
|---|---|---|
| 装修面层 | `INT_F2_BOARD_*` | 有洞（x 0.56–2.0 / z 1.76–2.86） |
| 结构板 | `INT_F2_SLAB_*` | 有洞，但洞口只覆盖折返跑的上半段 |
| **外壳整板** | **`VER_Slab`** | **11.1 × 10.2 m 的整块板，y≈3.52–3.60，横跨整个平面，没有洞** |

也就是说：面层和结构板都开了口，最下面那块外壳板又把洞口封死了。
另外 `INT_F2_SLAB_1`（x 0.56–2.0 / z 2.86–4.14）压在楼梯 A 跑上方，
站在一层能看到的只是「楼梯钻进天花板」。

## 做了什么（只改运行中的 GLB，不改他人脚本）

| 操作 | 对象 | 结果 |
|---|---|---|
| 删 | `INT_F2_BOARD_21/22/23` | 收掉压在 A 跑上方的三块地板，保留靠后墙的 `BOARD_20` 让后墙有落脚 |
| 删 | `INT_F2_RAIL_M_*`、`INT_F2_RAIL_E_*` | 这两段栏杆原本围住的是一条实心楼板，扩井后会把井口切两半 |
| 缩 | `INT_F2_SLAB_1` | z 由 2.86 收到 3.79，只在后墙下留 0.35 m 窄条 |
| 拆 | `VER_Slab` | 拆成 A/B/C/D 四块，中间让出 x 0.56–4.04 / z 1.76–4.14 的洞 |
| 补 | `scene/StairwellRailing.tsx` | 按原木作样式补西侧（x≈0.58）与北侧（z≈3.79）两段护栏 |
| 防跌落 | `mascotConfig.isOverVoid()` | 井口上方没有楼板，角色走到边缘会被挡住，不会掉下去 |

脚本：`scripts/gallery_edit.js`（按名字删网格 / 收板）、`scripts/cut_slab_hole.js`（拆板开洞）。
两份脚本都可以重复执行，执行前后各有一份 GLB 备份在 `assets/gallery3d/exports/`。

## 验证

- 井口可见：`docs/mascot/shots/m28-stairwell-open.png`、`m29-f2-edge.png`（从二层站在井边往下看得到踏步与光）；
- 上楼：一层 (0.35, 0.25, 3.40) → 平台 (3.08, 1.98, 3.40) → 二层 (-0.21, 3.60, 2.62)；
- 下楼：二层 (0.62, 3.60, 2.31) → y 2.99 → 2.42 → 1.98（平台）→ A 跑 → 一层；
- `tsc` 与 `vite build` 均通过。

## 重建模型时要注意

`VER_Slab` 的洞是直接改 GLB 实现的。若日后从 `mod_shell.py` / `mod_interior.py`
整体重建，需要在生成外壳时把这块整板也按洞口切成四块，否则洞会被重新封上；
`INT_F2_SLAB_1` 的 0.35 m 收窄同理。
