# 新图自动入展与三种互动

更新：2026-10-25。本文描述当前自动流水线；[此前构建记录](NEW_CASE_PIPELINE_20261024.md) 保留为历史，不代表当前实现或本轮指标。

## 用户操作

在创作台成功生成图像后，后端先保存作品、参考图、文化卡和参数，随即启动后台任务。作品无需手动入库；展厅自动显示构建状态，完成后开放 **画中有话、一图一境、画境漫游**。不需要编辑源码、人工补写文案或重启前端。

后台构建需要时间，不承诺三种互动与云端出图在同一个瞬间全部完成。保存与构建分开：构建失败也保留成功成图，并显示原因与重试入口。

## 模型职责

- **本地 Qwen3-VL / Ollama**：读取本件实际成图、选择热点、逐局部读取、撰写观察和专属三章叙事。仅允许本机地址及本地 Qwen3-VL；没有其他云端文本模型或人工文案替代。
- **本地 Depth Anything V2 Small**：估计这张图的相对深度，辅助 2.5D 显示；不撰写文化内容。
- **确定性代码**：图片哈希、裁切、结构校验、遮罩、完整白底主体分层、资产生成、保存与界面状态。
- **可选 DeepSeek 官方视觉复审**：查看原图、真实浏览器和五件精选参照，建议有限参数；出现语义问题时由本地 Qwen3-VL 再读本图修订。它不代写热点、章节或生成画境贴图。[复审依赖、预算和固定流程](DEEPSEEK_REVIEW_WORKFLOW.md)。

模型依赖、固定版本、许可、下载校验和权重交付见 [模型说明](../../models/README.md)。默认缺少深度权重时明确失败；后台不隐式下载。显式 `WENMAI_DEPTH_MODE=geometry` 仅是有标记的近似显示，不等于深度模型推理成功。

## 自动步骤

1. `POST /generate` 成功后，`case_store.save_case()` 保存独立 `caseId`。
2. `interactive_jobs.start_interactive_build()` 启动后台进程，持久记录排队、处理中、完成或失败。
3. Qwen3-VL 读取实际 `generated.png`，给出可见主体、构图类型、四处热点及相对层次。
4. 代码按坐标裁切；Qwen3-VL 分别读取整图与每一处实际局部，写对应观察、标题和审美解读。空白、重复标题、无效坐标或章节引用不能冒充成功。
5. Qwen3-VL 根据整图与本图局部观察写三章叙事，不复制同风格通用章节。
6. 本地固定版本深度模型读取同一成图；代码生成深度、贴图、遮罩和前景。山水采用平滑深度网格；确认白底的平面主体保留完整轮廓形成分层视差，避免长喙和细腿被网格拉扯。
7. 写入 `experience.json`、构建报告、`world.json` 及元数据。展厅通过接口更新状态，三个入口共享本件作品身份。
8. 明确启用复审后，最多三轮“真实浏览器采集 → DeepSeek 复审 → 有限调参或本地 Qwen 修订 → 重新采集”。只有达到策略且程序检查通过才标记复审通过；失败或到限保留原作与可用互动。

## 产物与绑定

```text
docs/examples/<caseId>/
├─ reference.png                # 实际输入（有参考图时）
├─ generated.png                # 真实成图
├─ culture_card.png
├─ metadata.json
├─ interaction-analysis.json    # 整图与逐局部 Qwen 输出、输入哈希
├─ experience.json              # 本件热点、章节与画境地址
└─ ingest-report.json

frontend/public/interactive/<caseId>/world/
├─ art.webp                     # 完整原作贴图
├─ surface.webp                 # 仅完整主体分层模式需要
├─ depth-rg.png
├─ model-depth-rg.png           # 分层模式保留实际估计深度
├─ depth-preview.png
├─ masks.png
├─ backdrop.webp
├─ cutout-subject.webp          # 成功提取时
└─ world.json                   # 实际资产、相机与模型来源
```

解析缓存绑定成图字节 SHA-256、提示、风格上下文及模型；深度缓存另绑定输入图像和固定模型 revision。同名换图不会复用旧解析或深度。画境资产有构建版本，重建后不会继续使用旧纹理。

## 运行期与静态部署

运行期使用 `GET /cases`、`GET /cases/{caseId}` 获取最新状态与本件互动；`/interactive/*` 动态提供刚生成的资产。不会以同风格旧作品替代新图，也不依赖 Vite 的启动时公共文件索引。浏览器后台图片缓存正确区分 Origin，支持普通图片预览与 WebGL 纹理使用。

静态构建通过 glob 纳入已提交的作品，GitHub Pages 只展示已打包资产；新作品需要重新构建部署。在线页面不运行 FastAPI、Ollama 或深度模型。

## 状态与恢复

任务持久化于 `backend/outputs/interactive_jobs.json`，不提交仓库。服务重启保留历史；中断任务标记失败，允许从展厅重试。相同作品的活动任务复用，避免并发写入。失败、超时和非零退出不会因为磁盘仍有旧文件就显示“就绪”。

```text
queued → processing → ready
                   → partial / failed → 用户重试
```

`POST /cases/{caseId}/interactions/rebuild` 只允许运行期作品；五件精选案例受保护。重试不再次调用收费生图服务。

`qualityReview` 是独立状态，不以 `ready` 代替质量验收。启用云端复审时，重新构建可能产生复审费用；已有案例只读浏览不发起复审。

## 验证与限制

本轮新增五种不同白底参考输入，分别经过真实图生图、自动保存、本地图像解析与画境构建。输入来自用户要求准备的 AI 测试素材，不是实物照片；浏览器验证和真实截图见 [本轮验收](../verification/20261025/README.md)。

自动热点仍属于估计位置，文化解读也不是历史事实核验。2.5D 只支持有限转头、前后移动和热点交互，不恢复遮挡背面；完整主体分层不等同于有骨骼的角色动画。低性能设备可降为静态视差，已生成作品不受影响。
